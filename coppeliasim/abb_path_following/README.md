# ABB moving-path following proof of concept

## Purpose

This CoppeliaSim scene validates the moving-reference path-following concept
before the Universal Robots and ROS 2 integration.

Robot 1 generates motion and carries the path structure. A target moves locally
along the path. Robot 2 solves inverse kinematics toward the resulting moving
target.

## Included files

- `scene/abb_path_following.ttt`
- `lua/robot1_motion.lua`
- `lua/path_target.lua`
- `lua/robot2_ik_following.lua`

The Lua scripts are embedded in the `.ttt` scene. Separate `.lua` copies are
included so that the source code can be inspected without opening CoppeliaSim.

## Required software

- CoppeliaSim
- simIK plugin

## Start-up procedure

1. Open `scene/abb_path_following.ttt`.
2. Verify that both robot models are present.
3. Verify that the path and moving target are present.
4. Verify that the simIK plugin is available.
5. Start the simulation.
6. Robot 1 generates the moving reference.
7. The target moves locally along the path.
8. Robot 2 follows the resulting target through inverse kinematics.

## Expected behaviour

The target world position is produced by the combination of:

- local target motion along the path
- path motion generated by Robot 1

Robot 2 follows this combined motion.

## Scene configuration and reset

This stage is simulation-only; ROS 2 and physical robots are not required.
Robot 2 resolves its base from `..`, its tip from `../tip` and follows
`/target2`. The IK element constrains position and alpha/beta orientation.
Renaming or reparenting these objects requires corresponding Lua changes.

The scripts executed by CoppeliaSim are embedded in the `.ttt` scene. The
separate `.lua` files are readable copies and must be kept synchronized with
the embedded versions. Stop and reload the scene before changing the path
hierarchy or initial robot configuration.
